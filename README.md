# ЛУДКА.COM

Учебная браузерная аркада. Только виртуальные монеты: нет платежей, продажи монет и вывода средств. Это локальный Node.js-проект, а не опубликованный сайт Sites: инструменты Sites и Notion в текущей сессии недоступны.

## Запуск в Windows и VS Code

1. Установите Node.js 22 или новее с официального сайта (проверено на Node.js 24).
2. Распакуйте исходники и откройте папку через **File → Open Folder** в VS Code.
3. В терминале PowerShell выполните `npm ci`, затем `npm start`.
4. Откройте браузер на локальном порту 3000. Зарегистрируйтесь: имя 3–24 символа, пароль минимум 8 символов.
5. Остановка сервера — Ctrl+C. Повторный `npm start` восстанавливает аккаунты, сессии и незаконченные игры из `data/arcade.json`.

Node.js не требует дополнительных пакетов для запуска сервера. Playwright нужен только для браузерных тестов. `npm ci` устанавливает зафиксированную dev-зависимость. Если npm не может записать пользовательский cache, используйте `npm ci --cache ./node-cache`.

Проверки: `npm test`; симуляция слотов: `node scripts/slot-math.mjs 100000`. Для браузерного QA: `npx playwright install chromium`, затем `npm run test:browser`. В облачной среде используется установленный `/usr/bin/chromium`; путь можно переопределить переменной `CHROMIUM_PATH`.

## Настройка окружения

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| PORT | 3000 | HTTP-порт |
| HOST | 127.0.0.1 | Адрес прослушивания; при размещении за reverse proxy используйте 0.0.0.0 |
| DATA_DIR | ./data | Постоянный каталог приватной базы; не размещать в public/ |
| COOKIE_SECURE | false | Установить true при HTTPS-размещении |

PowerShell: `$env:COOKIE_SECURE="true"`; `$env:HOST="0.0.0.0"`; `npm start`.

Для внешнего размещения необходимы Node.js-хостинг, HTTPS reverse proxy и постоянный диск. Нельзя размещать только public/ на статическом хостинге: аккаунты, RNG и расчёт выплат требуют сервера. Данные и сессии не хранятся в localStorage; там разрешены только настройки интерфейса.

## Архитектура

- `server.js`: HTTP, статические файлы, регистрация/вход/выход, серверные сессии, баланс, история, requestId и версия состояния.
- `lib/store.js`: единственный писатель, очередь транзакций, копирование состояния перед проверкой, временный файл + fsync + rename, резервная копия. После ошибки записи дальнейшие операции блокируются до проверки диска и перезапуска. При повреждённом основном JSON используется валидная резервная копия. Не запускайте несколько процессов с одним DATA_DIR.
- `lib/cards.js`: криптографическое перемешивание, подсчёт тузов и комбинаций пяти лучших карт.
- `lib/card-games.js`, `lib/chance-games.js`: игровые автоматы состояний; только сервер видит колоду, мины и crash point.
- `public/`: самостоятельный HTML/CSS/JavaScript-клиент, собственные SVG-элементы без внешних CDN.
- `tests/`: математика, правила, безопасность, конкурентные запросы и сохранение данных.
- `scripts/browser.mjs`: изолированный браузерный прогон, скриншоты ПК/телефона.

Пароли: scrypt с индивидуальной 128-битной солью, 64-байтный хеш. Cookie с HttpOnly, SameSite=Strict, сроком 7 дней; Secure включается для HTTPS. Сырые session token не сохраняются в JSON — только SHA-256. POST требуют JSON и проверяют Origin/Sec-Fetch-Site. Клиентские balance/payout/result игнорируются.

Все изменяющие баланс игровые запросы требуют уникального `requestId` и текущей `version`. Повтор того же запроса возвращает актуальное состояние без повторного списания; другой запрос с тем же ID отклоняется. Устаревшая версия отклоняется. Сохраняются последние 500 ключей; старые запросы дополнительно блокируются монотонной версией. Стоимость дополнительных карточных действий проверяется в той же транзакции, что и результат. В рулетке ставки целые: 1–500 на каждую внутреннюю позицию и 25–2000 на каждый шанс, дюжину или колонку. Повторные фишки на одной позиции суммируются. В остальных играх ставки кратны 10; ставка на банкира в баккаре кратна 20, чтобы комиссия 5% была целой.

Стартовый баланс — 50 000. Демонстрационное пополнение — 10 000, не чаще раза в 24 часа, только при балансе ≤5 000 и без активного раунда.

## Правила и математика

Точные исполняемые правила экспортируются как `RULES` в двух игровых модулях; таблицы линий и выплат — `SLOT_MATH`. Подробнее см. [RULES.md](RULES.md).

Варианты русского покера и Hold’em специально обозначены учебными. Hold’em не является Ultimate Texas Hold’em. Вероятностные игры используют crypto.randomInt. Никакие данные клиента не определяют исход.

Симуляция слотов показывает наблюдаемую частоту любых выплат, частоту прибыльных раундов, общую выплату и чистый результат. Это случайная выборка, не сертификация RTP и не гарантия будущих результатов. Три темы слотов используют одну математическую модель.

## Проверки и ограничения

Реально выполненные проверки и известные ограничения перечислены в [QA.md](QA.md). Тесты используют только временные базы и аккаунты. Артефакты помещаются в test-results/.

JSON рассчитан на один небольшой учебный процесс. Для масштабирования нужна транзакционная БД и распределённая идемпотентность. Не меняйте JSON вручную при работающем сервере. При некорректном lock-файле или незавершённой папке writer.lock.recovery остановите все процессы, проверьте владельца и данные перед ручным восстановлением. Резервные копии содержат приватные аккаунты и сессии и должны храниться отдельно от исходников.

Публикация в Sites, его предпросмотр, экспорт через Sites и загрузка в Notion не выполнены: соответствующих инструментов нет. Локальный ZIP создаётся отдельно без node_modules, data/, session cookies и тестовых баз. Для переноса в Sites сначала необходимо проверить поддержку Node.js и постоянного диска либо портировать сервер на поддерживаемые функции и транзакционную БД.

## Несколько боксов и слоты

В блэкджеке и баккаре доступны пять боксов. Введите номинал и нажимайте на нужные позиции; повторное нажатие добавляет фишку. «Очистить боксы» убирает расстановку. Общая первоначальная ставка не более 100 000. В блэкджеке дилер общий, ход выполняется по выделенной руке; один split разрешён отдельно на каждом боксе. Страхование покрывает все занятые боксы сразу. В баккаре каждый бокс может ставить на Игрока, Банкира и Ничью одновременно, расчёт общий по одной раздаче.

В слотах барабаны прокручиваются и останавливаются последовательно на результате сервера. При включённом уменьшении анимации в системе результат показывается сразу. Кнопка «Таблица выплат» открывает отдельное окно с коэффициентами и бонусами, загруженными из серверной конфигурации `/api/slot-math`.

## Результаты, рейтинг и карты баккары

Новое название интерфейса — ЛУДКА.COM. После завершения каждой игры открывается окно с исходной ставкой, всеми списаниями, общей выплатой и чистым результатом. Кнопка «Итог раунда» открывает его повторно. Выплата включает возвращённые ставки; чистый выигрыш/проигрыш считается отдельно.

Рядом со слотами постоянно видны коэффициенты и бонусы. 3+ Scatter дают 8 бесплатных вращений, 4+ — ещё и бонусный выбор. Бесплатные вращения сохраняют исходную ставку и не списывают монеты. Их количество, сыгранные вращения, выигрыш бесплатных игр и бонусные выплаты сохраняются на сервере и восстанавливаются после перезагрузки. Итог серии уже включён в общую выплату, повторно не начисляется.

Рейтинг открывается в навигации, профиле и подвале сайта: топ-50 по текущему балансу, включая стартовые монеты и демо-пополнения. Публично отдаются только имя, место и баланс.

В баккаре добавлены Пара игрока и Пара банкира: выплата 11:1, общий возврат 12×. Сравниваются достоинства первых двух карт, масть не важна; 10 и король не являются парой. История баккары хранит последние 200 раздач каждого игрока отдельно, начиная с этой версии. Окно «Статистика раздач» показывает Bead Road, Big Road, пары, ничьи и частоты. Это история, а не прогноз: колода перемешивается заново перед каждой раздачей.

Дополнительная проверка окон, бонусной серии и карт баккары: `npm run test:results`.
